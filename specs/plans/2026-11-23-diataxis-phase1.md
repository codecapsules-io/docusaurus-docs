# Diátaxis Restructure, Phase 1 (Structure Only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every doc into `docs/<type>/…` with new `/<type>/…` slugs, rewrite all internal links, rebuild navigation, and drop redirects, with no content edits.

**Architecture:** A small set of Node ESM scripts in `scripts/diataxis/` computes a move map from `DIATAXIS.md`, applies it (git mv, frontmatter), rewrites links with a link-aware parser, and verifies the result. Navigation becomes four autogenerated sidebars (one per type). Everything is deterministic and idempotent, so a bad run is fixed by resetting and re-running.

**Tech Stack:** Node 24 ESM (`.mjs`, matching `scripts/*.mjs`), `node:test` for tests, Docusaurus 3.10.

**Spec:** `specs/2026-11-23-diataxis-restructure-design.md`. Phase 2 (merges, extractions) is planned after phase 1 merges and is out of scope here.

## Global Constraints

- Four types only: `tutorial`, `how-to`, `reference`, `explanation`. Release notes stay in `release-notes/` at `/release-notes/`, untouched except link targets.
- Folders `docs/tutorials`, `docs/how-to`, `docs/reference`, `docs/explanation`; slug is `/` + path under `docs/` without extension, `/index` dropped (`docs/how-to/frontend/react.md` has slug `/how-to/frontend/react`). Existing slug style is `slug: "/x/y"` (double quotes, no trailing slash).
- Frontmatter gets `diataxis: <type>`, placed on the line after `slug:`.
- Phase 1 diff may touch only: frontmatter (`slug`, `diataxis`), file moves, link targets, nav config, removal of redirects config, `MANIFEST.md`, `DIATAXIS.md`, the four new landing pages and `_category_.json` files. Body text is otherwise byte-identical.
- No redirects. Remove `const redirects` and the `@docusaurus/plugin-client-redirects` plugin entry.
- `docs/index.md` keeps its path and slug `/`; it only gains `diataxis: how-to`.
- Docusaurus: `onBrokenLinks` is `warn`, `onBrokenMarkdownLinks` is `throw`, `trailingSlash: true`, docs `routeBasePath: '/'`. Gate is "no new broken links versus the baseline from `main`".
- Branch `brenton/diataxis`. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Tests: `node --test scripts/diataxis/`. New scripts follow the idiom of `scripts/normalize-gitbook-assets.mjs` (`node:fs/promises`, `process.cwd()` as root, no dependencies).

## Review Focus

1. A link with anchor, query or trailing slash (`/frontend/react/#set-up`, `/x?y=1`) keeps its suffix after rewriting.
2. `](/old/slug)` text inside a fenced code block is not rewritten, since it's example content.
3. A relative link (`./the-problem`, `../the-problem`, `foo.md`) that no doc resolves is reported and fails the run, never guessed.
4. Two old files mapping to the same new path, or a moved file landing on one of the four new landing-page paths, fails the plan step.
5. A moved doc's body is identical to the original apart from link targets (the "no content edits" gate).

### Task 2: Move map

**Files:**
- Create: `scripts/diataxis/lib/frontmatter.mjs`, `scripts/diataxis/plan-moves.mjs`, `scripts/diataxis/moves.json` (generated)
- Test: `scripts/diataxis/plan-moves.test.mjs`

**Interfaces:**
- Produces from `lib/frontmatter.mjs`:
  - `parseDoc(text: string): { frontmatter: Record<string, string>, body: string }` (simple `key: "value"` lines; `body` is everything after the closing `---` line, byte-exact)
  - `setFrontmatter(text: string, updates: { slug?: string, diataxis?: string }): string` (replaces the `slug:` line in place, inserts or replaces `diataxis:` on the next line, leaves every other line and the body byte-identical)
- Produces from `plan-moves.mjs`:
  - `loadLabels(diataxisMd: string): Map<string, string>` (old path to label: `tutorial|how-to|reference|explanation|hub|overview|release-notes`, from the `DIATAXIS.md` tables)
  - `resolveType(oldPath: string, labels: Map<string, string>): 'tutorial'|'how-to'|'reference'|'explanation'|'release-notes'`
  - `newLocation(oldPath: string, type: string): { newPath: string, newSlug: string }`
  - `planMoves(labels: Map<string, string>, oldSlugs: Map<string, string>): Move[]` where `Move = { oldPath, oldSlug, type, newPath, newSlug }`; throws on a new-path collision or a collision with a landing-page path
  - CLI: `node scripts/diataxis/plan-moves.mjs` writes `scripts/diataxis/moves.json` (all 234 entries, including unchanged ones)

**Rules:**
- `overview` is `explanation`. `hub` takes the most common type among the non-hub docs under its folder, ties broken in the order how-to, reference, explanation, tutorial. `release-notes` and `docs/index.md` never move (`docs/index.md` is typed `how-to`).
- `newPath` is `docs/<type>/` plus the old path under `docs/`, with a leading `products/` segment removed, except `docs/products/index.md`, which goes to `docs/how-to/products/index.md`.
- A doc from `docs/tutorials/` whose type is not `tutorial` goes to `docs/<type>/guides/<file>`.
- Explicit overrides: `docs/wordpress.md` to `docs/how-to/wordpress-capsule/managed-wordpress.md`; `docs/persistent-storage.md` to `docs/how-to/storage-capsule/persistent-storage.md`.
- Reserved landing paths (must not be taken): `docs/{tutorials,how-to,reference,explanation}/index.md`. The existing `docs/tutorials/index.md` hub is the one exception: it already is the tutorials landing page and stays put.

### Task 3: Apply moves

**Files:**
- Create: `scripts/diataxis/apply-moves.mjs`, `scripts/diataxis/landing-pages.mjs`
- Test: `scripts/diataxis/apply-moves.test.mjs`
- Modify: every doc under `docs/` (moved)

**Interfaces:**
- Consumes: `Move[]` from `moves.json`, `setFrontmatter`.
- Produces: `applyMoves(root: string, moves: Move[], { dryRun?: boolean }): Promise<void>`. For each move whose `newPath` differs: create directories, `git mv` (use `fs.rename` when `root` is not a git repo, so tests can run on a temp dir), then rewrite frontmatter with `slug: newSlug` and `diataxis: type`. For unchanged paths (`docs/index.md`, `docs/tutorials/*` that stay) only the frontmatter is updated. Release notes are skipped.
- Produces: `writeLandingPages(root: string): Promise<void>` creating `docs/{tutorials,how-to,reference,explanation}/index.md` (skipping `docs/tutorials/index.md`, which exists), each with frontmatter `slug`, `title`, `description`, `diataxis` of its own type, a one-paragraph intro, and `<DocCardList />` imported from `@theme/DocCardList`.

### Task 4: Rewrite internal links

**Files:**
- Create: `scripts/diataxis/rewrite-links.mjs`
- Test: `scripts/diataxis/rewrite-links.test.mjs`
- Modify: `docs/**`, `release-notes/**`, `src/**`, `docusaurus.config.ts`, `static/*.html`, `i18n/en/code.json` (only where a link targets an old slug)

**Interfaces:**
- Consumes: `Move[]`.
- Produces:
  - `buildResolver(moves: Move[]): (target: string, fromOldPath: string) => string | null | undefined` returns the new absolute slug (suffix kept), `null` for links to leave alone (external, `mailto:`, `#anchor`, `/gitbook-assets/…`, `/img/…`, `/openapi/…`, `/release-notes…`, asset extensions), and `undefined` for an internal link that no doc resolves.
  - `rewriteLinks(text: string, fromOldPath: string, resolve): { text: string, unresolved: string[] }` rewrites `](target)`, `href="target"`, `to="target"` and `src="target"` occurrences outside fenced code blocks; keeps `#anchor`, `?query` and a trailing slash exactly as written.
  - CLI: `node scripts/diataxis/rewrite-links.mjs` rewrites every file in the scope above (using the old path of each moved file from `moves.json`) and exits non-zero, printing `file: target`, if any link is unresolved.

Resolution rules: an absolute target is looked up by old slug (trailing slash ignored); a relative target is resolved against the directory of the file's *old* path, trying `<t>`, `<t>.md`, `<t>.mdx`, `<t>/index.md`; both give the move's `newSlug`.

- [ ] **Step 1: Write failing tests** (exact values):
  - `](/frontend/react)` in any file becomes `](/how-to/frontend/react)`
  - `](/frontend/react/#set-up)` becomes `](/how-to/frontend/react/#set-up)`
  - `](/products/alerting?x=1)` keeps `?x=1`
  - from old path `docs/agentic-automation/index.md`, `](./the-problem)` becomes `](/explanation/agentic-automation/the-problem)`
  - from `docs/products/database-capsule/mongodb/versions/upgrades/7-0-to-8-0.md`, `](../versions)` resolves relative to the old directory (use a real sibling in the fixture)
  - `href="/frontend/react"` in JSX is rewritten; `](https://example.com/x)`, `](#top)`, `](/gitbook-assets/a.png)` are untouched
  - a fenced block containing `](/frontend/react)` is untouched
  - `](./does-not-exist)` appears in `unresolved` and the text is unchanged
  - applying `rewriteLinks` to its own output changes nothing (idempotent)
- [ ] **Step 2: Run to see failures, implement `buildResolver`, `rewriteLinks` and the CLI.**
- [ ] **Step 3: Run `node --test scripts/diataxis/`.** Expected: PASS.
- [ ] **Step 4: Run for real:** `node scripts/diataxis/rewrite-links.mjs`. Expected: exit 0, a summary of files changed and links rewritten (about 1,000). If it lists unresolved links, fix each by hand in the doc, record them in the commit message, and re-run.
